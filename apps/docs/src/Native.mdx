# Native (`@reactive/silk-native`)

React Native renderer for Silk. Same semantic `Theme` object and recipe
contracts as `@reactive/silk` — delivered through React context, **not** CSS
variables. Native should feel native; web should feel like the web.

Stories under **Native Components** and the **Fixtures/NativeShell** /
**Fixtures/NativeSettingsForm** pages render these components via
`react-native-web` so the docs site can exercise them without a simulator. The
real-native exit demo is `apps/native-example` (Expo).

## Install

```bash
yarn add @reactive/silk-native @reactive/silk-core
# peers: react ^19, react-native >=0.83
```

```tsx
import { createTheme } from '@reactive/silk-core';
import {
  Box,
  Button,
  Card,
  Field,
  Heading,
  Inline,
  Input,
  SilkProvider,
  Stack,
  Switch,
} from '@reactive/silk-native';

const theme = createTheme({ colorScheme: 'light' });

export function Screen() {
  return (
    <SilkProvider theme={theme} density="comfortable">
      <Box padding="4">
        <Card padding="4">
          <Stack gap="3">
            <Heading level="2">Hello</Heading>
            <Field.Root>
              <Field.Label>Name</Field.Label>
              <Input />
            </Field.Root>
            <Inline gap="2" align="center">
              <Switch accessibilityLabel="Notify" />
              <Button>Save</Button>
            </Inline>
          </Stack>
        </Card>
      </Box>
    </SilkProvider>
  );
}
```

## Shared vs divergent

| Concern | Shared (`silk-core`) | Web | Native |
| --- | --- | --- | --- |
| Tokens / Theme | `createTheme`, semantic colors, space, radius, typography, measure | CSS vars + `data-theme` | Context `{ theme, density }` |
| Recipes | `defineRecipe` axes + defaults | `data-*` + Linaria | Style objects via mappers |
| Density | `compactSpace` export | CSS aliases under `data-density` | Pick scale in mapper |
| Interaction | Visual axes only | `:hover` / `:focus-visible` | `Pressable` pressed + disabled |
| Layout extras | — | `asChild`, `collapseBelow`, CQ | Omitted (platform-justified) |
| Fonts | CSS stacks in `fontFamily` | Full stack | First named face (or system) |
| Measure | Character count | `max-width: Nch` | `fontSize × N × 0.6` (`ch` ≈ 0.6em) |
| Escape hatches | — | CSS vars → `className` → `style` | `style` (last) + `ref` + RN props |

## Theme nesting

- Omitted `theme` / `colorScheme` → reuse parent `Theme` identity
- Explicit `colorScheme` → fresh default theme for that scheme (replaces a parent tenant theme)
- Explicit `theme` → used as-is; wins over `colorScheme`
- Density inherits independently; root default is comfortable
- Nested `SilkProvider` `defaults` **replace** the parent map (no component-level merge)

## Escape hatches (native ladder)

1. Theme / provider defaults / recipe props (same axes as web)
2. `style` applied **after** Silk styles (Button supports object / array / function `Pressable` styles)
3. Typed `ref` to the host view / text / pressable
4. Remaining React Native host props

No public CSS variables or `className` on native.

## Control geometry

Button / Input / Checkbox / Switch / Spinner geometry is **renderer-local**,
expressed as density-aware space steps (parallel to web `controlGeometry.ts`) —
not core tokens. Avatar `mediaScale` sizes stay density-independent (content).

## Native adaptations (documented)

| Web | Native |
| --- | --- |
| Skeleton shimmer gradient | Opacity pulse (plain RN views) |
| Indeterminate Progress 35% solid-over-sunken mix | Static `tone.subtle` fill under reduced motion |
| Spinner 25% `color-mix` ring | `tone.subtle` + `tone.solid` (no color-string parsing) |
| `accessibilityLiveRegion` | Android-only enhancement; use roles + labels cross-platform |
| Slider: Radix pointer capture, hidden form inputs | Responder drag from the slider's own location; no `name` / form inputs; Page and Shift keys on the web only |
| Slider: marks positioned by the caller | `children` draw under the thumbs and take no touches; `useSliderMarkStyle()` places them |
| Tooltip: Radix `aria-describedby` on the trigger | Trigger is a box, so the control inside carries the same words (`accessibilityHint`) |
| Roving keyboard focus (RadioGroup) | Screen readers navigate elements directly |

RNW tests assert ARIA aliases (`aria-checked`, `aria-valuenow`, …) via the
`a11yState` / `a11yValue` helpers — RN object props alone are dropped by RNW.

## Shipped components

**Layout:** Box, Stack, Inline · **Visual:** Text, Button, Surface, Card,
Heading, Badge, Separator, Avatar, StatusDot, Skeleton, Spinner, Progress ·
**Forms:** Input, Textarea, Field, Checkbox, Switch, RadioGroup, Slider ·
**Overlays:** Dialog, Popover, Tooltip, Listbox · **Paging:** Pager, with

## Overlays

`Dialog`, `Popover` and `Listbox` are controlled (`open` / `onOpenChange`,
`value` / `onValueChange`) and have no Trigger or Close parts: the app's own
button sets `open`, and gives `Popover.Root` its `anchor` ref.

```tsx
const anchor = useRef<View>(null);
<Button ref={anchor} onPress={() => setOpen((was) => !was)}>{size}</Button>
<Popover.Root open={open} onOpenChange={setOpen} anchor={anchor}>
  <Popover.Content size="sm" align="start">
    <Listbox.Root accessibilityLabel="Size" value={size} onValueChange={setSize}>
      <Listbox.Item value="Small">Small</Listbox.Item>
      <Listbox.Item value="Large">Large</Listbox.Item>
    </Listbox.Root>
  </Popover.Content>
</Popover.Root>
```

| | Web (react-native-web) | Android |
| --- | --- | --- |
| `Dialog` | `Modal`: `aria-modal` dialog, focus trap, focus back to the opener, Escape | `Modal`: back button, modal to TalkBack |
| `Popover` | Non-modal Radix `DismissableLayer` and untrapped `FocusScope` in a body portal: the page stays live, so a menu can open on hover | Transparent `Modal`; back button |
| `Tooltip` | Popover's layer, never focused; opens on a resting mouse or keyboard focus, and on a press nothing inside takes | Transparent `Modal`, opened by a tap nothing inside takes; a tap anywhere closes it |
| `Listbox` | `listbox` / `option`, one Tab stop, arrows / Home / End / Space | `radiogroup` / `radio` |

A `Popover` closes on a press outside it and its anchor (on native the layer
covers the anchor, so a press there closes it too), Escape or the back button, a resized window, scrolling that moves the anchor, and a pick (or Tab)
in a `Listbox` inside it; focus inside it goes back to the anchor. On the web,
a `Popover` or `Tooltip` inside a `Dialog` opens over it, inside its focus trap,
and Escape closes it without closing the dialog.

`Tooltip` has web's parts; `Tooltip.Provider` is optional. Its `Trigger` is a box around the
control, so a disabled control (which takes no press) still opens it on a tap:

```tsx
<Tooltip.Root>
  <Tooltip.Trigger>
    <Switch accessibilityLabel="Hints" accessibilityHint="Only in Explore" disabled checked={false} />
  </Tooltip.Trigger>
  <Tooltip.Content>Only in Explore</Tooltip.Content>
</Tooltip.Root>
```

Screen readers don't read the tooltip from the trigger, so give the control the
same words. Keyboard focus can't land on a disabled control, so on the web its
tooltip opens only for a mouse or a tap.

A `Listbox.Item` with custom children colors its text with `Listbox.ItemText`,
which follows the item's state the way a plain string label does.

## Paging

`Pager` is controlled like the overlays: it shows the page `value` names, and
a swipe only proposes the page it lands on. An owner that keeps `value` sees
the pages settle back. Answer in the same update or in a transition: an answer
that comes later (after an `await`) arrives after the pages settled back.

```tsx
<Pager.Root value={pane} onValueChange={setPane} style={{ flex: 1 }}>
  <Pager.Page value="moves"><Moves /></Pager.Page>
  <Pager.Page value="notes"><Notes /></Pager.Page>
</Pager.Root>
```

The drag runs on the UI thread and moves at most one page; on release it
springs to the nearest page, or to the next one on a fling, at the finger's
speed. A `disabled` page is passed by, to the next page beyond it. A page
that isn't shown is hidden from screen readers (and `inert` on the web);
inside it, `usePagerIsActive()` is false, so it can stop listening.
On the web a mouse drag pages too, so the pager's text can't be selected, and
it doesn't also press what it began on.

`useFlickGesture({ direction, onFlick })` returns `{ gesture, touchAction }`
to spread onto a `GestureDetector`; `onFlick` runs once when a finger throws
the view that way and lets go at fling speed.

## Stage 1 spike findings (folded forward)

What worked without core changes: numeric dimensions, unitless `lineHeight`,
recipe contracts, semantic colors, `compactSpace` as a parallel export,
`createTheme` Theme via context.

Justified divergences remain as in the table above. Nested provider inheritance
and `Inline` shipped in Stage 6 (they were spike simplifications).
