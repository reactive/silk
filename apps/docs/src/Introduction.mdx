# Silk

`@reactive/silk` is a long-lived design system foundation for React (web). Radix owns behavior; Silk owns visuals, APIs, and theming through **semantic tokens + CSS variables** and **Linaria static extraction**.

This Storybook is the primary docs site for the library (tracks `main`).

## Packages

| Package                 | Description                                              |
| ----------------------- | -------------------------------------------------------- |
| `@reactive/silk-core`   | Platform-neutral tokens, `createTheme`, recipe contracts |
| `@reactive/silk`        | Web design system (Radix + Linaria)                      |
| `@reactive/silk-native` | React Native renderer (context themes, no CSS variables) |

Composites can also ship as source via the [shadcn registry protocol](https://github.com/reactive/silk/blob/main/registry.json). Registry items pin compatible `@reactive/silk` versions. Zero Tailwind.

## Install

```bash
yarn add @reactive/silk
# peer: react / react-dom ^19
```

## Quick start

Consumers must import the extracted stylesheet once. Fonts are optional — see **Theming → Typography and fonts**:

```tsx
import { Button, Identity, SilkProvider, createTheme } from "@reactive/silk";
import "@reactive/silk/styles.css";
import "@fontsource-variable/inter";
import "@fontsource-variable/source-serif-4";
import "@fontsource-variable/jetbrains-mono";

export function App() {
  return (
    <SilkProvider
      colorScheme="light"
      defaults={{ Button: { variant: "soft" } }}
    >
      <Button tone="accent">Save</Button>
      <Identity name="Ada Lovelace" meta="@ada" fallback="AL" />
    </SilkProvider>
  );
}
```

Custom / tenant themes use the style-attribute path:

```tsx
<SilkProvider
  theme={createTheme({ semantic: { color: { surface: "#fafafa" } } })}
>
  …
</SilkProvider>
```

## Customization levels

1. `createTheme(...)` — semantic theme
2. `SilkProvider` `defaults` — typed per-component defaults
3. Component props — `variant` / `tone` / `size` / `density` / …
4. Escape hatches — public component CSS variables, `className`, `style`, slots / `asChild`

### Choosing an escape hatch

They are ranked rather than interchangeable. Start with the **public CSS variables** a component exposes (`--silk-button-bg`, `--silk-surface-shadow`, …): the component only reads them, so your declaration always wins.

Prefer **`styled(Component)`** from `@linaria/react` when you want a reusable named component (or typed dynamic props that compile to CSS variables):

```tsx
import { styled } from "@linaria/react";
import { Button } from "@reactive/silk";

const DangerButton = styled(Button)`
  --silk-button-bg: var(--silk-color-tone-danger-solid);
  --silk-button-radius: var(--silk-radius-full);

  &:hover:not(:disabled) {
    --silk-button-bg: var(--silk-color-tone-danger-hover);
  }
`;

<DangerButton>Delete</DangerButton>;
```

Prefer **`css` + `className`** from `@linaria/core` when the style is a mixin — shared across hosts, stacked with `cx`, or a one-off that does not deserve a wrapper component:

```tsx
import { css, cx } from "@linaria/core";
import { Box } from "@reactive/silk";

const surface = css`
  border: 1px solid var(--silk-color-border-subtle);
  border-radius: var(--silk-radius-md);
`;

const narrow = css`
  max-width: 20rem;
`;

<Box className={cx(surface, narrow)} padding="4">
  …
</Box>;
```

Both extract at build time and can carry state, media, and container selectors. `styled` wrapping a Silk component skips the DOM-tag prop filter; dynamic interpolations compile to CSS variables on `style` (prefer a `data-*` prop for custom inputs). `@linaria/react` is optional. Silk itself uses only `@linaria/core`.

Reserve Silk's `cssVars` + `style` for values you only know at runtime and do not want to model as a prop:

```tsx
import { cssVars } from "@reactive/silk";

<Button style={cssVars({ "--silk-button-bg": tenant.brandColor })}>
  Save
</Button>;
```

### Cascade order

Silk keeps every rule at single-class specificity (variants use `:where([data-…])`), so a consumer class is a tie that stylesheet order breaks. If you need that guaranteed rather than incidental, import the layered stylesheet instead — its rules live in `@layer silk`, which any unlayered rule of yours outranks:

```tsx
import "@reactive/silk/styles.layer.css";
```

The trade-off: an unlayered global reset of yours will also outrank Silk. Put your reset in a layer too and declare the order — `@layer reset, silk;`.

## Architecture

The authoritative architecture write-up lives in the repository:

[docs/ARCHITECTURE.md](https://github.com/reactive/silk/blob/main/docs/ARCHITECTURE.md)

Hard constraints: no Tailwind, no CVA, Linaria static extraction only, SSR-first, accessibility behavior from Radix whenever possible.

## Local docs development

```bash
yarn docs           # watch-builds silk-core + Storybook on :6006
yarn docs:build     # static site → apps/docs/storybook-static
```

Storybook aliases `@reactive/silk` to source (HMR) but loads `@reactive/silk-core` from `dist/`. `yarn docs` keeps that dist fresh. The preview decorator applies `createTheme()` as inline CSS variables for light/dark, so token edits show up after the core rebuild without a Storybook restart (toolbar **system** still uses static named themes).
