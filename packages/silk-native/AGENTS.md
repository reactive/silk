Traps in `silk-native` that its code and tests do not make obvious. Paths are under this package.

- Anything that moves under a finger runs on the UI thread: Gesture Handler for the gesture, Reanimated shared values for the position, and `springTo` for the release. Build a drag with `panAlong` and `useReleaseTimer` (`src/gesture/drag.ts`). The exception is a control that moves on press, as Slider's web pan does.
- On the web, Gesture Handler writes each attached handler's `touch-action` and `user-select` onto the detector's view, a disabled handler's too, and the last write wins. Never compose a disabled gesture with an enabled one in one `GestureDetector`: leave it out of the composition (`src/components/useSliderDrag.ts`). Set `touch-action` in the gesture's config, as `panAlong` does (`src/gesture/drag.ts`), never through the detector's `touchAction` prop or a style: Gesture Handler applies a gesture's config after the detector attaches it and drops the detector's value then. `src/gesture/touchAction.test.tsx` runs the real Gesture Handler to check it.
- Tests run worklets uncompiled. `src/worklets.test.ts` (it covers `silk-core` too) pins what only the worklets Babel plugin's output breaks: read its comments before writing a worklet, and add each new failure there.
- An animated style reruns only for shared values its own body reads. Read them there, pass plain numbers to helper worklets, and pass `WEB ? [those values] : undefined` as its dependencies (`src/components/sliderMotion.ts`).
- Gesture tests mock Gesture Handler and call its configs by hand (copy `src/components/Slider.drag.test.tsx`). Only Storybook play tests run it for real, and there it hears pointer events, not mouse events (`apps/docs/src/native/Forms.stories.tsx`). A play test's synthetic pointer can't be captured, so moves outside the view are dropped, and a `panAlong` pan starts a frame after the move that passes the slop: keep a play drag on the view and wait a frame after that move (`SwitchDrag` there).
- rstest refuses an async mock factory. Import the real module with `import * as x from '…' with { rstest: 'importActual' }`.
- A mechanic this package owns because no behavior library provides it is listed under "Current bindings" in `docs/PRINCIPLES.md`, with a dated "Amendment log" entry, and pinned by a test.
- A platform-chosen `#…` import (`#floating-layer`, `#in-text`, `#motion-list`) is mapped in four places that must agree: `package.json` `imports`, this package's `rstest.config.ts`, and the docs app's `.storybook/main.ts` and `rstest.config.ts` (the last three to the web file).
- `MotionList`'s native engine keeps a row's speed through an interrupted glide only because Reanimated hands each property's running animation to the next layout animation, where `springTo` reads its `velocity`. After a Reanimated upgrade, run `MotionList/speedHandoff.test.ts` first; if it fails, retrace Reanimated's `layoutReanimation/animationsManager.native.ts`, `valueSetter.ts` and `animation/styleAnimation.ts`. `springSpeed` (Pager's relist) reads the same private handoff, a shared value's running `_animation`, and no test runs it against the real Reanimated: after an upgrade, confirm in `valueSetter.ts` that a value's animation is still kept on `_animation`.
- Reanimated skips CSS animations and transitions when `NODE_ENV === 'test'`, and reads a numeric keyframe selector as a fraction (0 to 1), so write `'50%'`, `from`, `to`. Unit tests read the style from a stand-in `Animated.View` (copy `src/components/loops.test.tsx`); only a Storybook play test sees them run (`apps/docs/src/native/Visual.stories.tsx`, `LoadingLoops`).
